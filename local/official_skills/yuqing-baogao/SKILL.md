# 报告生成（周报 / 月报 / 季度报 / 年报）

当用户的请求匹配本 Skill 的能力时启用。你是通用智能体上的专项能力，不是独立专家 Bot：完成任务后仍保持通用助手身份。

本 Skill 抽象自 aibank **周期性报告**能力（`ReportService` / `report_config` / `report_text_generator`）：
**一律按「年报模板」结构生成，再按报告类型做减法**（章节更少、TOP 更短、短周期不做月度对比）。

> 不要与「数据处理」(shuju-chuli) 混淆：本 Skill 产出的是对客 **Word 监测报告**，不是打标 Excel。  
> 也不要走 excel2report 那套「封面导读+倾向/走势四章精美月报」版式；以本节年报四章模板为准。

## 启用约束（最高优先级）

1. **必须**确认报告类型为：**周报 / 月报 / 季度报 / 年报** 之一（用户未指定则先问；口语「季报」=季度报）。
2. **必须**确认：监测主体（机构名）、起止日期（或可推断的周期）。
3. **必须**有数据来源：用户上传的已清洗/已标注明细表，或工作区内可统计的舆情明细。无数据则请用户补材料；缺打标可建议先 `shuju-chuli`，但本 Skill 本身按「已可统计的明细」写报告。
4. **最终交付物必须是 `.docx`**，并用 `send_file_to_user` 发送；聊天给指标摘要，附件不能替代章节正文说明。
5. **禁止编造**条数、占比、媒体名、标题、事件、处置量；数字只能来自明细统计。缺字段则降级并写明，不要填假数。

## 可用工具

| 工具 | 用途 |
|------|------|
| 工作区文件 | 读取明细 `.xlsx` / `.csv` 等 |
| 代码执行 | pandas 统计；matplotlib 出图；python-docx 组 Word |
| `web_search` / `web_fetch` | 仅用户明确要求补公开背景时；**不得**用检索结果改写统计数字 |

# 报告类型配置（对齐 report_config，含周报扩展）

周期性报告共用同一套四章模板；差异只在：默认章节、是否月度对比、TOP 长度、风险提示条数。

| 类型 | 枚举参考 | period_label | 默认章节 | 月度信息对比 | 热点/平台 TOP | 风险提示条数 | 标题模板 |
|------|----------|--------------|----------|--------------|---------------|--------------|----------|
| **周报** | `WEEKLY_PUBLIC_OPINION` | 本周 | 概况+正面+敏感 | 否 | 5 | 0 | `{机构}舆情周报【{年}年{月}月{日起}-{月}月{日止}】` |
| **月报** | `MONTHLY_PUBLIC_OPINION` | `{month}月` | 概况+正面+敏感 | 否 | 5 | 0 | `{机构}舆情月报【{年}年{month}月】` |
| **季度报** | `QUARTERLY_PUBLIC_OPINION` | `第{quarter}季度` | 概况+正面+敏感 | 是 | 10 | 0 | `{机构}舆情季报【{年}年第{quarter}季度】` |
| **年报** | `YEARLY_PUBLIC_OPINION` | 全年 | 概况+正面+敏感+**风险** | 是 | 10 | **9** | `{机构}舆情年报【{年}年】` |

说明：
- aibank 后端现网生成对话框还有「半年报 / 自定义」；**本 Skill 默认只做用户点名的四种**。若用户明确要半年报，按年报结构、风险提示 **5** 条、period_label 上/下半年处理即可。
- 「月度信息对比」仅当周期覆盖 **≥2 个自然月** 时输出；周报/单月月报即使勾选也不出该小节。
- 用户可勾选模块（见下）；未指定则用上表默认章节。

## 可选模块（对齐 reportModules）

**章节（进 Word 正文）**
- `text_overview` 舆情信息概况  
- `text_positive` 正面信息分析  
- `text_sensitive` 敏感信息分析  
- `text_risk` 下阶段舆情风险提示  

**图表分析扩展**（有数据则可附在文末「图表分析」章；做不出则跳过并说明）  
信息类型分布、来源占比、媒体类型占比、来源/敏感/互动走势、网民情绪、媒体活跃度、活跃作者、媒体级别、敏感占比+TOP、发布规律热力图、热门话题、词云等。地图/行业网络等重图可不进 Word。

# 数据口径（对齐 ReportService._collect_template_data）

从明细表（或等价字段）统计；时间落在 `[period_start, period_end]`。

## 1. 信息属性四分（互斥，合计=总量）
- **正面 / 中性 / 敏感** + **消费者网络匿名投诉**
- 「负面」在报告中写作 **敏感**
- 投诉优先：信息分类/备注类型为「客户投诉」的条目计入 `complaint`，不再计入其余三类
- 输出：`total`、各类 count 与占比（保留 2 位小数）
- **风险等级**（按敏感占比）：≥20% 高；≥10% 中；否则 低

## 2. 信息来源（传播渠道）
按媒体类型汇总，规范中文名：客户端 / 网站 / 微信 / 微博 / 互动论坛 / 视频 / 数字报 / 其他等。每项含 count、ratio。

## 3. 热点话题 TOP N
正面、敏感各一份：按**标题**聚合，传播量=命中条数；附重点媒体/账号（来源站点去重拼接）。N 见类型表。

## 4. 媒体平台 TOP N
正面、敏感各一份：按来源网站计数；记录参与发布的平台总数；榜首平台可抽 1–3 条样本标题供正文引用。

## 5. 月度序列（需月度对比时）
逐月：positive / neutral / sensitive / complaint / total；缺月补 0。敏感高峰月取 sensitive 最大的月份。

## 6. 处置（可选）
敏感信息中状态为已处置/resolved 的条数与处置率。  
**无处置字段或处置量为 0 时**：不要写「处置 0 条 / 处置率 0% / 应对不力」；策略段只给应对思路。

## 字段映射（常见列名，有则用）
日期：`日期` / `发布时间` / `publish_time`  
标题：`标题` / `标题/微博内容` / `title`  
情感：`打标_四分类` / `信息属性` / `sentiment`（负面→敏感）  
媒体类型：`媒体类型` / `media_type`  
来源：`来源网站` / `source_site`  
分类：`信息分类` / `remark_type` / `info_category`  
处置：`status` / `处置状态` 等

# 章节骨架（年报模板四章）

Word 结构：**封面 → 目录 → 正文章节（按启用模块）→（可选）图表分析**。

## 封面
- 报告标题（用类型标题模板）
- 监测主体、周期起止（写成「X年X月X日」）
- 成文日期可用中文数字日期

## 一、{period_label}舆情信息概况（text_overview）
### 1、信息属性分析
规则拼数段（总量与四分占比 + 风险等级）+ 属性分布饼图  
### 2、{period_label}月度信息对比（仅跨月且配置开启）
走势说明 + 月度组合图  
### 3、信息来源分析
渠道数据段 + 点评段（集中度、短板渠道建议；勿逐条复读全部数字）+ 来源柱/饼图  

## 二、正面信息分析（text_positive）
### 1、正面亮点信息展示与分析
亮点段（条数、占比、热点方向；热词须来自话题标题）+ TOP 表（序号 / 热门标题 / 重点媒体 / 相关传播量）  
### 2、正面媒体平台分析
平台段（平台数、TOP 占比、榜首平台样本标题）+ TOP 柱图  

## 三、敏感信息分析（text_sensitive）
### 1、敏感舆情信息概述
概述段 +（有处置时）处置成效句 + 敏感 TOP 表  
### 2、敏感舆情平台分析
平台数据段 + 分析段（榜首平台传播机理与治理建议，可 250–350 字）  
### 3、敏感舆情应对策略分析
策略段（汇报/举报/投诉/媒体沟通/引导等）；无处置数据时禁止评价「应对是否到位」  

## 四、下阶段舆情风险提示（text_risk，年报默认；周/月/季默认不出）
引言 + N 条「标题 + 分析建议」。标题形如「重点关注……引发的声誉风险」，覆盖监管处罚、信息披露、薪酬、服务体验、个人信息保护、员工行为、突发事件等不同维度，不得重复、不得编造本期未出现的具体事件细节。

# 叙述规则（对齐 report_text_generator）

## 文风
- System 口径：只依据给出的数据写作；输出偏公文段落；分析段通常 150–250 字；平台/策略段可 250–350 字  
- Word 内不要 Markdown 符号；不要空章——分析写不出时回退规则模板句  

## 概况倾向（规则模板示例）
> {年}年{周期}（{起}-{止}），共监测到{机构}有效信息{total}条（篇），其中正面信息{pos}条，占{pos_pct}%；中性信息{neu}条，占{neu_pct}%；敏感信息{sen}条，占{sen_pct}%；消费者网络匿名投诉类信息{comp}条，占{comp_pct}%。根据舆情属性分布情况看，{机构}舆情风险等级：{level}。

## 摘要一行（列表/封面可用）
> 共监测到 {total} 条舆情，其中敏感舆情 {sensitive_count} 条，占比约 {sensitive_ratio}。

# 处理流程

1. 澄清类型（周/月/季/年）、机构、周期、数据文件  
2. 读表、字段映射、过滤周期内有效行  
3. 按类型配置计算 attr / sources / topics / platforms /（月度）/ disposal  
4. 生成各槽位正文（数据段规则；分析段可归纳）  
5. `python-docx` 渲染：页边距约 1 英寸；封面、目录、章节、表头深蓝底白字、正文仿宋  
6. 保存 `deliverables/{机构}-舆情{周报|月报|季报|年报}-{周期}.docx`  
7. `send_file_to_user` + 聊天摘要  

# 输出格式（聊天）

## 1. 报告说明
（类型、机构、周期、数据来源、纳入条数）

## 2. 核心指标
（总量与正/中/敏感/投诉及占比、风险等级）

## 3. 章节速览
（启用章节各一句）

## 4. 文件交付
`.docx` 路径 + 已 `send_file_to_user`

## 结构硬约束（验收）
1. 类型只能是周报/月报/季度报/年报（或用户明示的半年报）  
2. 必须交付 `.docx`；聊天含 `## 1` `## 2` `## 4`  
3. 章节必须符合该类型默认（或用户勾选）配置；年报须含风险提示章（除非用户明确去掉）  
4. 周报/月报默认无「月度信息对比」、无风险章；季度报有月度对比、无风险章  
5. 所有数字可回溯统计；无处置数据禁止写处置率 0% / 应对不力  
6. 不与 shuju-chuli 抢打标流程；不套用 excel2report 精美月报另一套章节名  

## Word 交付
1. 路径建议：`deliverables/<机构>-yuqing-baogao-<周|月|季|年>-<周期>.docx`  
2. 必须 `send_file_to_user`  
3. 写文件失败时一行说明原因，并在聊天贴出完整章节正文兜底；能写 docx 时不得只交兜底
